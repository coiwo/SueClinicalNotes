## 1 最初目标与电脑条件

Sue 请助手阅读 sourceFile 的两个 Word 文档：保险病历工具架构计划、本地 Docker 搭建指南。目标是针灸诊所的私密 OON 保险病历工具，重点是上一份病历加本次变化生成复诊草稿，而非每次从零开始。

检查到电脑为 Intel Core i5 四核、8 GB 内存、macOS 15.7.7。起初约 11 GB 空闲空间，Git 已有，Node 和 Docker 未装。讨论过外置 SSD：可增加存储，但不能增加内存。Sue 尚未购买，计划以后买。后来空闲空间升到约 24–26 GiB，可开始开发。

## 2 项目工作方式

Sue 指定 app-building-virtual-assistant 文件夹，并要求遵循 AGENTS.md，用非技术人员能理解的方式逐步带领。最初路径不可访问，后改到正确文件夹并成功读取。

## 3 真正的工作痛点

Sue 确认构想符合需求。最耗时的是找到病人旧病历，再根据本次病情组织记录；也担心保险公司认为病情不够严重而拒付。

决定：帮助准确表达真实治疗依据、功能限制和变化，提示缺项；不能夸大病情、编造改善、伪造次数或保证付款。界面喜欢墨绿色。

## 4 现有 ChatGPT 网页与两个压缩包

Sue 已用 ChatGPT 制作一个私密网页，并给过它一些保险文书要求。链接无法由当时的浏览工具访问，因此 Sue 提供截图。

截图展现墨绿色和米白背景、左侧输入右侧预览、缺项提示、复制/TXT/PDF 和规则依据库。页面自己标注 OWNER ONLY、BROWSER LOCAL，以及部分规则已验证；这些标识不能替代访问控制、网络或政策核验。

首个压缩包是首轮测试记录，不含源码。记录的问题包括：疼痛 11/10 可进入病历；30 分钟时段可填 999 分钟直接接触；修改表单后可能导出旧预览；中文输入可能残留在英文输出；缺项输出的草稿策略需要明确。

第二个压缩包 clinical-note-prototype.zip 有零依赖 HTML/CSS/JS 本地重建代码，但不是原网页完整源码。包含表单、固定模板、输入校验、复制/下载/打印及测试；无数据库、登录、自动保存或自动翻译。所有 payer 规则标为待核验。决定参考和复用适合的逻辑，不直接当成最终系统。

## 5 名称、语言和登录

Sue 暂定名称 SUE Clinical Notes，以后可改。界面中英混合，但最终 notes 必须纯英文。选择密码登录，便于本人在其他电脑使用或给同事访问。获知密码的人可新增/修改；共享密码不能识别具体操作人。个人账号和 Google 登录不是第一版必须项。

## 6 Square、诊疗日期和次数

Sue 用 Square 预约，希望 App 显示病人信息与预约时间，不必另查何时来诊。还需要补录实际诊疗、更正误录日期和统计次数。

明确确认 Square 只读同步到 App；App 内的变动不回写 Square。预约与实际诊疗分开，取消或未到诊预约不自动算治疗。病历修改版本不增加治疗次数。定稿后的更正要保留原文和原因，不能静默覆盖。

Square 官方接口有客户/预约能力，但尚未连接账号、核实授权或实现同步。

## 7 远程访问与未来申报

Sue 要求自己的 Mac 关机时，其他电脑仍可登录使用。因此正式版本需要持续运行的服务器，不能仅靠本机或同网络访问。服务商、预算、区域、协议、HTTPS 和访问保护未选定；没有购买或部署。

Sue 以后希望生成保险公司使用的红色申报表，初步识别为 CMS-1500/HCFA-1500。留到后续阶段，并区分生成表格与真正提交理赔。

## 8 旧记录、sample 和备份

旧病历大约几十份，混合 Word 和 PDF，格式不一致。另有约 20 份按病情、主诉及穴位准备的 sample，希望助手帮助完善。sample 部分纯示例，部分有真实姓名、生日等。

约定原文件保留，不上传真实患者文件到聊天或未经确认的 AI。先分类、去身份处理，小批试读并核对；扫描 PDF 是否需要 OCR 尚未确认。确切资料文件夹待导入阶段确认。

尚无外置硬盘，备份目的地待定；真实资料启用前仍需每日自动备份、独立目的地、保留期限和实际恢复测试。服务器备份不能依赖 Sue 的 Mac 开机。

## 11 环境安装与 Phase 1

Sue 自行安装 Node.js；实际检查得到 Node 24.21.0、npm 11.19.0。随后安装 Intel 版 Docker Desktop，实际验证 Docker 29.8.0、Compose 5.5.1，并成功运行 hello-world。Docker 命令安装在个人路径，测试时补充工具 PATH。

采用 create-t3-app 建立 sue-clinical-notes 子文件夹，使用 Next.js、TypeScript、Tailwind、Prisma/SQLite。外层保留计划说明，内层放代码。基础墨绿色首页通过类型和 HTTP 检查，Sue 确认可打开。此阶段用 npm run dev，后续才为日常运行打包 Docker。

## 12 Phase 2 数据库

建立 Patient、Encounter、Visit。Encounter 是一次实际诊疗；Visit 是对应病历版本，防止修改版本影响诊疗次数。提供虚构数据 4 位病人，每人 3 次诊疗，共 12 份草稿，覆盖改善、不变、加重、未记录评分。

迁移中遇到 SQLite JSON 默认值格式问题，已修正迁移并验证通过。保护规则包括疼痛范围、版本唯一、保存历史、定稿不可覆盖/删除、更正需引用同次诊疗的定稿且有原因、病人用归档代替删除。测试事务会回滚，不污染演示资料。

Sue 在 Prisma Studio 看到 4 人和 12 份记录，但觉得表格很丑、字段挤成一行，不如原网页。助手说明这是开发管理工具，不是最终界面。这个反馈促成提前展示实际用户页面。
