先看这份说明
============

继续现有项目：最简单的用法
--------------------------
现在项目里已有三个真正可选择的技能：
  myvirtualassistant-start
  myvirtualassistant-changelog
  myvirtualassistant-check-progress

Codex CLI / IDE：输入 /skills 打开技能列表，或输入 $ 搜索技能。
ChatGPT 界面：使用 @ 选择技能，具体入口以客户端为准。
如果新技能没有出现，重新启动 Codex 并打开 SueClinicalNotes 项目。
这些技能放在项目根目录的 .agents/skills/；分享项目时要一起提交和拉取。
这不会把 /my 注册为原生斜杠命令菜单。

在 Codex 中打开主项目 SueClinicalNotes，并新开一个会话。
项目根目录的 AGENTS.md 会让助手默认使用这套开发流程。
在聊天框输入以下任意口令即可，不要在终端输入：

  myvirtualassistant    或「继续开发」：接着上次的进度工作
  myvirtualassistant-start：同样用于开始或继续今天的开发
  myvirtualassistant-changelog：按模板生成或更新本次任务的变更记录
  myvirtualassistant-check-progress：核对代码和 changelog，先确认进度再继续
  查看进度：查看目前完成了什么、下一步是什么
  今天做完了：总结、整理 changelog，并按你的授权处理 Git 提交和上传

也可以直接输入「继续开发，今天我想改进病人搜索」。
这些是聊天口令，不是内置斜杠命令，不需要加 /。
如果客户端允许将斜杠文字作为普通消息发送，也可以用：
  /myvirtualassitant-start
  /myvirtualassistant-start
  /myvirtualassistant-changelog
  /myvirtualassistant-check-progress
开始口令的两种拼写都支持；如果提示未知命令，去掉开头的 / 再发送。
changelog 口令会把记录保存到 docs/Sue's changelogs/，已有同一任务的
记录就更新，不会重复创建，也不会因此自动提交、上传或结束今天的工作。

check-progress 口令适合隔天回来或换一个新会话时使用。助手会只读检查
当前代码、分支、未提交改动、最近提交、项目计划和 changelog，告诉你
已完成什么、还有什么没完成、记录与代码是否一致，以及建议的下一步。
然后会问你进度是否准确、有没有遗漏、是否可以做建议的下一步。
在你回复确认前，不会修改代码、安装依赖、改数据库、提交或上传。
若使用已经打开的旧会话，先说「请读取项目根目录的 AGENTS.md」。
下面的从零搭建说明仅供新项目参考；继续现有项目不需要重做安装和搭建。

每次修改后的变更记录
--------------------
继续已有项目时，助手会先查看当前分支、未提交的修改和最近的变更记录，
再跟你确认今天要做什么，以及做完后是先本地测试，还是提交并上传到 GitHub。
不会重新安装或从头创建项目。

到合适的收尾时间，助手会问“今天先做到这里吗，还是还要继续改？”
默认由助手自动整理下面的变更记录；你也可以要求每次先问你是否要生成。
已经确认过的选择不用重复确认。上传前会说明实际改动和目标分支；
如果你还没有授权上传，助手会先问你。说“今天做完了”不代表自动上传。

每次完成新功能、修复、设置或说明文档的修改后，助手会主动把变更记录写到
项目根目录下的 docs/Sue's changelogs/ 文件夹，使用里面的 TEMPLATE.txt 格式。
文件名为 YYYY-MM-DD-short-description.txt，记录改了什么、为什么改、
涉及哪些文件、实际验证结果、你可以怎么检查，以及还有什么没做完。
你不用自己记住所有细节；提交代码前，确认这份记录也和相关文件一起提交。
记录里不要放密码、访问令牌或真实病人资料。

这个文件夹里有几份给 Codex 看的文件（AGENTS.md 是主文件，另外两份是以后可选的升级），
你自己不需要看懂里面的内容——那是写给 Codex 的技术指令。你只需要跟着下面几步操作，
剩下的全部由 Codex 主动带着你一步步做，包括：

- 检查你电脑上有没有装好 Docker、需要的话指导你安装
- 帮你把整个 App 的代码搭出来（数据库、登录、几个核心页面）
- 用 Docker 把 App 打包好，方便以后随时开关
- 最后帮你把你那 200 份 Word 历史病历导入进去（这一步它会先问清楚细节，
  不会一上来就乱导）

每完成一个阶段，Codex 会停下来告诉你"现在应该看到什么"，等你确认了再继续，
不会一口气全做完让你看不懂发生了什么。


怎么开始，总共就三步
--------------------

第一步：找到这个文件夹在你电脑上的位置

把整个文件夹（包含 AGENTS.md 这几个文件的那个文件夹）保存到你电脑上一个你
好找的位置。既然你已经有一个"Documents（文稿）→ Project"的文件夹在放这个
项目相关的东西，建议直接把这个文件夹也放进 Project 里面——不管 Project
里面现在是空的还是已经有其他子文件夹，放进去就行，下一步会用"拖拽"的方式
定位，不需要你自己打路径、也不需要搞清楚里面具体的文件夹结构。


第二步：打开终端，进入这个文件夹

- 按住 Command 键 + 空格键，输入 "Terminal" 或"终端"，回车打开。
- 输入 cd 这个单词，后面加一个空格，然后把这个文件夹直接拖进终端窗口里
  （拖进去会自动帮你把路径打好），再按回车。
  举例大概长这样（你自己拖进去的路径可能不完全一样，因为它取决于你把
  文件夹放在 Project 里的哪个位置——不用管这个，拖对了终端会自动帮你写好）：

  cd /Users/你的用户名/Documents/Project/app-building-virtual-assistant

第三步：启动 Codex，让它开始按说明一步步带你做

如果这台电脑还没装过 Codex（比如你在公司那台 Mac 上，之前只在家里
那台装过），先按下面这几行装好：

- 在终端里输入并回车：
  npm install -g @openai/codex
  （如果提示找不到 npm 这个命令，说明这台电脑还没装 Node.js，先去
  nodejs.org 下载安装包装好，装完重新打开一个新的终端窗口再试一次）
- 装完之后，在终端里输入：
  codex
  回车，第一次会要求你登录账号（用你平时登录 ChatGPT 的账号就行），
  跟着提示登录即可。

如果这台电脑已经装过 Codex，直接跳到下面这步。

在终端里输入：

  codex

回车，等它打开。打开后，直接跟它说这样一句话（把下面框里的话原样
复制粘贴给它就行，这是最关键的一步）：

  ────────────────────────────────────────────────
  请读取这个文件夹里的 AGENTS.md，按里面的说明来。我没有技术背景，
  请按你自己的开场流程来，一步一步带我把这个 App 搭起来。
  ────────────────────────────────────────────────

发送之后，Codex 会先像个真人助手一样跟你打个招呼、简单介绍一下接下来
要一起做什么，然后问你准备好了没有。你说"准备好了"之类的话，它就会
开始正式聊——先问你一些问题（比如登录方式想要哪种、要不要接 Google
日历、界面想用中文还是英文等等），根据你的回答生成一份专属的方案，
念给你听、等你确认没问题了，才会真正开始动手搭建。

确认方案之后，接下来的每一步它都会主动问你、主动解释、主动等你确认。
你只需要照着它说的做，卡住的时候把报错内容截图或复制给它，问它"这是
什么意思，要怎么办"就行。中途任何时候想不起来现在能做什么、有哪些
功能可以加，跟它说一句"帮助"就行（后面有专门一节讲这个）。

每一步做完，Codex 会先自己偷偷验证一遍确实没问题（不是随便跑完命令
就直接跟你说"好了"），遇到报错也会先自己想办法查、想办法修，修不好
才会来问你——所以大部分时候你不会看到真正的报错，卡住基本都是它自己
先处理过一轮之后还是搞不定的情况。跑比较久的步骤（比如装东西、搭数据库）
它也会先说一声"这个可能要一两分钟"，不会让你干等着不知道是不是卡住了。


整个过程大概会经过这几个阶段（Codex 会自动一步步走，你不用自己记）
--------------------------------------------------------------------
先聊：Codex 跟你打招呼、讲清楚要做什么，问你一连串问题（登录方式、
      要不要接 Google 日历、要不要远程访问、历史病历的情况、界面
      语言、备份想存哪等等），根据你的回答生成一份方案文档，念给你
      确认没问题后才开始动手。

0. 先检查一个隐私设置——因为第 7 步要处理你真实的历史病历，Codex 会
   先带你确认 ChatGPT 账号里"允许用我的对话改进模型"这个开关关掉了
   没有（设置 → Data Controls → Improve the model for everyone，
   关闭），另外 Codex 自己还有一个独立的开关（在 Codex 自己的设置里，
   叫 Include environments 之类的名字），这个和上面那个是两回事，
   两个都要关。Codex 会一步步带你去找，确认你真的关掉了才会继续往
   下走。然后再检查/安装 Docker 和 Node（App 运行需要的基础环境）
1. 把项目代码骨架搭出来——这一步会在你现在这个文件夹里面，新建一个
   用你刚才起的 App 名字命名的子文件夹（比如叫 meridian-notes），
   真正的 App 代码都会放进这个子文件夹里。看到 Finder 里多出一个
   新文件夹是正常的，不是出错了；从这一步开始，后面每一步 Codex
   实际操作的都是这个子文件夹，你现在这层（放 AGENTS.md 的这层）
   就只用来放说明文档，不会再变动。这一步 Codex 也会先用一个叫
   npm run dev 的快速方式跑起来给你看一眼——这是"搭建期间"用的
   临时跑法，方便边搭边看；等第 6 步正式用 Docker 打包好之后，
   日常用的就是 Docker 那一套了。这不是反复横跳、出错了，是搭建
   阶段和正式使用阶段本来就是两种跑法，Codex 会提前说清楚。
2. 建好数据库结构——这一步会打开一个叫 Prisma Studio 的小工具，
   在浏览器里能直接看到"这是你的病人表，这是刚才建的几个假病人"，
   不是看一堆看不懂的终端文字。
3. 按你选的方式搭登录（简单密码或 Google 账号登录，"先聊"那步已经问过了）
4. 搭出几个核心页面（病人列表、新建病人、复诊更新等）
5. 建好保险公司规则的空结构（真实规则以后你提供资料再填）
6. 用 Docker 把整个 App 打包，并且会给你做两个可以直接双击的小图标
   （一个用来开、一个用来关），以后日常用不需要开终端敲命令
7. 帮你把 200 份历史 Word 病历导入数据库（会先问清楚文件夹位置、
   格式是否统一，小批量测试没问题再正式导入）


关于界面语言
------------
Codex 会在最开始那轮问题里问你：App 界面（按钮、菜单这些你天天看的
东西）想用中文还是英文。但生成给保险公司看的 note 本身，不管你选哪个，
永远都是英文——因为是给美国保险公司看的，这个没得选，只有界面语言
可以选。


关于 google-auth-upgrade.md
----------------------------
这份不用等以后——"先聊"那一轮问题里，Codex 就会直接问你想用哪种：
一个人用的简单共享密码（快，现在就能用），还是正式的 Google 账号登录
（适合以后诊所里可能不止你一个人用，设置起来会多花几步）。当场选就行，
不用先记住这份文件。如果一开始选了简单密码，之后随时想换成 Google
登录，也可以跟 Codex 说"请按 google-auth-upgrade.md 帮我把登录方式
换成 Google 登录"。


关于 google-calendar-integration.md
-------------------------------------
这份也先不用管。以后如果想在 App 里直接看到你 Google 日历上的预约
（比如今天有哪些病人要来、点一下直接跳到对应病人的页面），再跟
Codex 说"请按 google-calendar-integration.md 帮我把 Google 日历接进来"
就行。这个功能只会读取你的日历、不会改动你日历上的任何东西，而且
跟上面那个"换成 Google 登录"是两件独立的事，先做哪个、要不要做
都不影响另一个。


关于 remote-access-setup.md
------------------------------
你家里和公司各有一台 Mac，如果想在公司也能打开家里那台跑着的 App，
跟 Codex 说"请按 remote-access-setup.md 帮我设置远程访问"就行。这份
指南用的是一个叫 Tailscale 的免费工具，两台 Mac 都装上、登同一个账号，
公司那台就能安全地连到家里那台，不会把这个 App 暴露在公开的互联网上——
不需要花钱买域名，也不需要在路由器上开端口。唯一要注意的是：家里那台
Mac 得开着、没有睡眠，公司才连得上，这份指南里也会教你怎么设置"不自动
睡眠"。


以后日常怎么打开这个 App（搭完之后）
--------------------------------------
不用每次都开终端、敲命令。搭建完成后，Codex 会在那个 App 子文件夹里
给你放两个可以直接双击的小图标：一个叫 start-app（开）、一个叫
stop-app（关）。想用的时候双击 start-app，浏览器打开对应网址就行；
用完双击 stop-app 关掉。

唯一要注意：**Docker Desktop 这个 App 本身得先开着**，双击才会有用——
这不是搭建时候确认一次就完事的事，是以后每次要用都需要的前提。如果
双击 start-app 没反应，先去"应用程序"里打开 Docker Desktop，等它
显示"running"再试一次。也可以让 Codex 帮你把 Docker Desktop 设置成
"开机自动启动"，这样就不用每次都自己记得先打开它了。


随时想看看有哪些选项，跟 Codex 说"帮助"就行
----------------------------------------------
不管搭建到哪一步，只要想不起来现在能做什么、有哪些功能可以加、
或者忘了怎么切换语言，随时跟 Codex 说一句"帮助"或者"有什么选项"，
它会给你列一个简单的小清单：怎么切换语言、Google 登录/Google 日历/
远程访问这几个可选功能分别是什么、现在搭到哪一步了、卡住了该怎么办。
看完之后它会接着刚才没做完的事继续，不用担心问了"帮助"会打断进度。

语言想切随时切，不用特意说一声——中途直接改用另一种语言打字，
Codex 会自动跟着换，来回切换都可以。

这份说明本身也不是写死的
--------------------------
AGENTS.md（也就是这整份指导 Codex 怎么帮你搭建的文件）不是固定不变
的。搭建过程中如果你觉得哪里想改一下规则、加一个新要求，直接跟
Codex 说就行，它会帮你把这份文件也一起更新，不只是当次照做完就忘了。


如果卡住了
----------
把终端里的报错内容（红色文字）整段复制，或者直接截图，问 Codex：
"这个报错是什么意思，我要怎么办？" 不需要自己看懂任何一行代码或命令。


如果原本好好的东西突然不能用了——有"后悔药"
------------------------------------------------
Codex 在搭建过程中，背地里一直有个"存档点"机制（你不需要懂这是什么，
也不用管），每完成一步确认没问题，它都会偷偷存一个档。所以如果哪天
突然发现"这个功能昨天还好好的，今天点了没反应"，直接跟 Codex 说：

  "这个东西之前是好的，最近是不是改坏了？能不能退回到能用的那个版本？"

Codex 就会自己去找最后一个"确认没问题"的存档点，退回去或者只把
改坏的那部分改回来，不用从头重搭。你不需要知道它具体怎么操作的，
只要这样开口说就行。
