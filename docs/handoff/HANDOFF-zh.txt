Sue 临床笔记 — 交接文档
========================

这是一个本地、密码保护的应用，供针灸师 Sue 撰写、修改和导出临床病历。
所有数据保存在 Sue 的 Mac 上，不会发送到任何外部服务。


------------------------------------------------------------------------
从 GitHub 获取项目
------------------------------------------------------------------------

代码仓库：https://github.com/coiwo/SueClinicalNotes


首次 — 克隆项目
----------------

    git clone https://github.com/coiwo/SueClinicalNotes.git
    cd SueClinicalNotes
    git branch                  （应显示：main）


获取最新代码 — 克隆后更新
--------------------------

    git checkout main
    git pull


常用 Git 命令
-------------

    git status                              查看哪些文件有改动
    git log --oneline                       查看提交历史
    git checkout <分支名>                    切换到其他分支
    git checkout -b feature/your-name      创建并切换到新分支
    git add .                               暂存所有改动
    git commit -m "描述你改了什么"            提交改动
    git push origin feature/your-name      将分支推送到 GitHub

建议：在自己的分支上工作（不要直接改 main），这样不会和他人的修改冲突。
完成后在 GitHub 上发起 Pull Request，将改动合并回主分支。


------------------------------------------------------------------------
启动应用
------------------------------------------------------------------------

前提条件：Node.js 18+，npm

    1.  npm ci                           安装依赖
    2.  npx prisma migrate deploy        应用数据库迁移
    3.  npm run db:seed                  导入虚构测试数据（推荐）
    4.  npm run dev                      启动开发服务器

然后打开：http://localhost:3000/login

首次登录：系统会提示你设置密码（12–128 个字符）。设置一次后，之后直接用
该密码登录。如需重置密码，删除 storage/private/access.json 并重启即可。

------------------------------------------------------------------------
主要操作流程
------------------------------------------------------------------------

新增病人
  1. 点击顶部导航栏的"新增病人"（或访问 /patients/new）
  2. 填写病人编号、保险公司、治疗部位、就诊日期、疼痛评分（0–10）
  3. 填写临床信息：活动范围、病人主诉、客观检查、评估、计划
  4. 点击"保存病人和草稿 / Save patient and draft"
  5. 页面跳转至该病人的详情页，显示已保存的草稿

新增复诊
  1. 进入病人详情页（从"病人档案"中选择病人）
  2. 点击"新增复诊 / New visit"
  3. 填写新的就诊日期、疼痛评分，以及与上次相比的变化
  4. 保存后创建新草稿，上一次病历版本保留可查

编辑草稿
  1. 在病人详情页找到状态为"草稿 Draft"的病历
  2. 点击"Edit draft"，表单会预填当前内容
  3. 保存后生成新版本（v2、v3 等），历史版本仍可查看

定稿
  1. 在病人详情页打开需要锁定的草稿
  2. 点击"Review and finalize"
  3. 病历状态变为"定稿 Final"，永久锁定，无法再编辑

打印 / 导出完整病历历史
  1. 进入任意病人的详情页
  2. 点击"Export full history as PDF"（或打印按钮）
  3. 浏览器下载包含该病人所有定稿和草稿的 PDF 文件

搜索病人
  在主工作台（/）或"病人档案"页面使用搜索栏。
  可按病人编号、治疗部位或保险公司名称搜索。


------------------------------------------------------------------------
项目结构
------------------------------------------------------------------------

    src/
      app/
        api/access/[action]/   登录、退出、会话检查接口
        actions.ts             所有服务端操作（新增病人、保存病历等）
        page.tsx               主工作台页面
        login/                 登录和密码设置页面
      server/
        access-store.ts        密码哈希、会话令牌、锁定逻辑
        access.ts              会话 Cookie 工具函数
      components/              UI 组件：病人卡片、病历编辑器、预约列表等

    prisma/
      schema.prisma            数据模型
      migrations/              SQL 迁移文件（含手写触发器）
      seed.ts                  导入 4 位虚构病人共 12 次就诊

    storage/private/           access.json 存放于此（已加入 .gitignore）
    db.sqlite                  数据库文件（已加入 .gitignore）
    .env                       环境变量，包含 ngrok 的 APP_ORIGIN


------------------------------------------------------------------------
常用命令
------------------------------------------------------------------------

    npm run dev              启动开发服务器（localhost:3000）
    npm run typecheck        TypeScript 类型检查
    npm run db:verify        数据库完整性检查
    npm run test:access      认证逻辑单元测试
    npm run db:seed          重新导入虚构测试数据
    npm run db:studio        打开 Prisma Studio 浏览数据库

重要：应用迁移时始终使用 "npx prisma migrate deploy"，
禁止使用 "prisma db push"。迁移文件包含手写触发器，db push 会悄悄将其删除。

注意事项
------------------------------------------------------------------------

重置密码：
  删除 storage/private/access.json，重启服务器，然后访问 /login 重新设置。

定稿病历无法编辑，这是设计如此：
  如需修改，使用附录流程（UI 尚未完全接入），或重新导入演示数据。

仅为演示数据：
  种子数据包含虚构病人（DEMO-ONLY-001 至 004），所有病历均标注
  "FICTIONAL TEST DATA"。

依赖安全审计：
  当前存在 2 个严重和 4 个高危漏洞（位于间接依赖中）。本地测试可用，
  部署真实病人数据前必须先修复。

NextAuth 脚手架：
  User/Session/Account 表存在于数据库 Schema 中，但未被使用——应用使用自定义
  认证系统，忽略这些表即可。
