SUE'S CHANGELOGS

Keep a short record here for each feature, fix, setup change, or documentation
change. The assistant should write it before handing the work back to Sue.
Automatic recording is the owner's default. If Sue asks to confirm first
or explicitly declines an entry, respect her preference and report it.
At a natural stopping point, confirm whether she is finished for the day
unless she has already said so. Writing a log does not authorize a Git push.

HOW TO ADD AN ENTRY
1. Copy TEMPLATE.txt to a new file in this folder.
2. Name it YYYY-MM-DD-short-description.txt using the actual local date.
   Example: 2026-09-24-local-setup-guide.txt
3. Replace every placeholder. Use "None" or "Not run: reason" when applicable.
4. Record actual results, including failures and anything still pending.
5. Include the entry with the related changes in the same Git commit.

Use one entry per coherent task. Update that entry while the task continues.
For a different task with the same filename, add -02, -03, etc. Do not
overwrite an unrelated entry. English or Chinese descriptions are fine;
keep the template's field labels and section order consistent.

The author is whoever made the change; do not automatically credit Sue
for work performed by the owner or assistant. Do not include credentials,
real patient information, or private database contents.

For documentation-only changes, checking the text, paths, and formatting
is sufficient; explicitly say app tests were not run because code did not
change. Sue's confirmation stays pending until she actually confirms.
