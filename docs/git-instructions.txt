======================================================================
SECTION 2: GIT SETUP (AFTER CLONING, BEFORE MAKING COMMITS)
======================================================================

The following setup commands are for Sue to run on her own computer.

2A. Set Sue's commit name and email
----------------------------------

Run these commands inside the SueClinicalNotes folder to set the author
information for future commits in this repository:

git config user.name "Sueduthebest"
git config user.email "sue.du.work@gmail.com"

Check the saved settings:

git config user.name
git config user.email

These settings apply only to this repository. They do not change existing
commits or switch your GitHub login.

2B. Sign in to GitHub as Sueduthebest
-----------------------------------

To sign in using GitHub CLI (gh), run:

gh auth login --hostname github.com --git-protocol https --web

Complete the browser login as Sueduthebest. If the browser is signed in to
another account, switch to Sueduthebest before completing authorization.
Then run:

gh auth setup-git
gh auth status

Confirm that the active GitHub account is Sueduthebest. If multiple accounts
are already saved and another account is active, run:

gh auth switch --hostname github.com --user Sueduthebest
gh auth status

If you see "gh: command not found", install GitHub CLI from https://cli.github.com/
and then repeat the login steps.

2C. Get permission to push to the repository
------------------------------------------

Complete the preparation section above. Once Sue accepts the collaborator
invitation as Sueduthebest, she has write access to this personal repository.
The owner does not need to enable a separate Write setting.

2D. Fix a permission error (403)
-------------------------------

If a push reports "Permission to coiwo/SueClinicalNotes.git denied to
Lucas-makerCDD" with error 403, Git is using credentials for Lucas-makerCDD.
Changing git config user.name or user.email alone will not fix this.
Complete the GitHub login and repository access steps above, then retry
the push once your feature branch and commits are ready:

git push origin feature/sue-1

======================================================================
SECTION 3: PULL THE LATEST CHANGES FROM MASTER
======================================================================

Before switching branches, commit your current work or stash it.

git checkout master
git pull --ff-only origin master

======================================================================
SECTION 4: CREATE OR CHECK OUT A FEATURE BRANCH
======================================================================

Start from the updated master branch, then run:

git checkout -b feature/sue-1

This creates feature/sue-1 and switches to it. Use a new name, such as
feature/sue-2, for the next task.
To switch to an existing local branch, omit -b:

git checkout feature/sue-1

======================================================================
SECTION 5: COMMIT AND PUSH YOUR FEATURE CHANGES
======================================================================

After editing your files, review your changes:

git status
git diff

Stage, review, commit, and push:

git add .
git diff --cached
git commit -m "your notes"
git push origin feature/sue-1

Replace "your notes" with a short description of what you changed.
Run git add . from the repository root to stage all changes, including
deletions. Check the staged changes before committing to make sure they
contain only the files you intend to share.
Repeat these steps whenever you have more changes to push.

======================================================================
SECTION 6: PULL CHANGES FROM THE REMOTE FEATURE BRANCH
======================================================================

With your current work committed or stashed, run:

git checkout feature/sue-1
git pull --ff-only origin feature/sue-1

This downloads updates that someone else pushed to the same feature branch.
It does not bring master changes into your feature branch.
If --ff-only reports that the branches have diverged, stop and resolve the
branch history with your collaborator before pushing.

======================================================================
SECTION 7: MERGE INTO MASTER AND PUSH MASTER
======================================================================

First, complete Section 5 so your feature changes are committed and pushed.
Then run:

git checkout master
git pull --ff-only origin master
git merge feature/sue-1

Review the merged result and run the project's relevant checks. Once ready:

git push origin master

This publishes the merged changes to the remote master branch.
If Git reports merge conflicts, edit the conflicted files to resolve them,
then run:

git add .
git commit -m "Resolve merge conflicts"

Review and check the result before running git push origin master.
To cancel an unfinished merge instead, run git merge --abort.

If master is protected and direct pushes are blocked, push feature/sue-1
and open a pull request from feature/sue-1 into master on your Git host.
Complete the required reviews and checks, then merge the pull request there.
